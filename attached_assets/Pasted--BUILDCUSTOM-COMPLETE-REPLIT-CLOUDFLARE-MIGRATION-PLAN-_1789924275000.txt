# BUILDCUSTOM COMPLETE REPLIT → CLOUDFLARE MIGRATION
## PLAN MODE ONLY — DO NOT IMPLEMENT ANYTHING YET

We have reached an important milestone with BuildCustom.

BuildCustom is an AI software-building platform similar conceptually to Replit:
users describe what they want to build, our native AI coding agent builds it,
they preview it, edit it conversationally, publish it, and host it through
BuildCustom.

Our native BuildCustom coding agent/runtime is the current Cloudflare VibeSDK
agent/runtime, branded as BuildCustom.

We are NOT building a second AI agent around VibeSDK.

VibeSDK/ThinkAgent is the native coding agent.

BuildCustom owns the product/control plane around it:
- users
- authentication
- projects
- permissions
- billing
- usage
- project metadata
- domains
- deployments
- platform actions
- UI/UX
- future customer database provisioning
- future storage provisioning
- future external agent/API/MCP access

Cloudflare/VibeSDK owns the underlying coding/runtime infrastructure:
- ThinkAgent
- SpaceDO
- workspace/files
- Cloudflare Artifacts/revision history
- code execution
- Dynamic Worker previews
- sandbox/container execution where required
- Workers for Platforms deployment
- generated application runtime

==================================================
WHY WE ARE DOING THIS MIGRATION NOW
==================================================

BuildCustom itself was originally developed on Replit.

Replit has been useful as our development environment, but it must NOT remain
a production infrastructure dependency.

Before we continue building full-stack functionality for generated customer
applications, including:

- databases
- customer authentication
- signup/login
- persistent application data
- file storage
- secrets
- queues
- additional Cloudflare bindings

we want BuildCustom itself completely migrated to Cloudflare.

The purpose of this phase is:

TURN REPLIT OFF AND BUILDCUSTOM STILL WORKS.

That is the primary acceptance criterion.

When this migration is complete:

- BuildCustom's production frontend must not depend on Replit.
- BuildCustom's production API must not depend on Replit.
- BuildCustom's production database must not depend on Replit.
- BuildCustom authentication must not depend on Replit.
- BuildCustom sessions must not depend on Replit.
- BuildCustom project metadata must not depend on Replit.
- BuildCustom domain metadata must not depend on Replit.
- BuildCustom deployment metadata must not depend on Replit.
- BuildCustom secrets must not depend on Replit.
- BuildCustom's VibeSDK integration must not depend on Replit.
- BuildCustom's generated application hosting must not depend on Replit.
- Existing published applications must not depend on Replit.
- Existing custom domains must not depend on Replit.
- BuildCustom must continue functioning if the Replit deployment is completely
  stopped.

Replit may remain temporarily useful as a DEVELOPMENT ENVIRONMENT while we
finish the migration.

It must no longer be production infrastructure.
