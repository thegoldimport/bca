→ UNDERSTAND
→ TARGETED DISCOVERY
→ EDIT
→ PREFLIGHT
→ REPAIR IF NEEDED
→ COMMIT / PREVIEW

→ COMPLETE

The customer should experience ONE coherent coding operation.

==================================================
6. ADD WORKING-TREE PREFLIGHT
==================================================

This is launch-critical.

Current deploy_space commits before building.

That is unsafe for malformed intermediate code.

Implement a narrow internal SpaceDO working-tree preflight capability.

It must validate the CURRENT WORKING TREE:

WITHOUT:
- git checkout
- commit
- deploy
- reset
- restore
- mutation

Factor/reuse the existing compilation/build logic where practical.

The preflight must operate on the working-tree snapshot, not merely Git HEAD.

Also validate static source that may not be compiled by the Worker bundler when necessary.

Project 5 proved this matters because malformed public/app.jsx could otherwise survive until after commit.

Return structured diagnostics to Think.

On failure:

- preserve dirty working tree
- feed diagnostic to primary agent
- allow repair if progress/budget remains

==================================================
7. FIX deploy_space ORDERING
==================================================

Current problematic behavior:

commit
→ build/deploy

and commit exceptions are caught too broadly.

Change the safe path to:

working-tree preflight
→ if PASS
→ commit
→ branch preview deployment
→ browser/runtime verification

Do not treat every gitCommit exception as "clean tree."

Distinguish:

- genuinely clean tree
- successful commit
- actual commit failure

A real commit failure must surface as a real failure.

Never silently deploy stale HEAD because a commit failed.

==================================================
8. ADD EXPLICIT COMPLETION INTENT
==================================================

Prefer a small structured Think tool such as:

finish_task

rather than parsing natural-language claims like:

"Done!"
"Everything is complete!"

The tool represents PRIMARY AGENT INTENT to finish.

It does NOT itself make the operation COMPLETE.

The host completion gate must still verify required evidence.

For a code-changing task, COMPLETE requires:

- primary agent finish intent
- requested changes present to the extent mechanically verifiable
- working-tree preflight success
- successful deploy_space
- deployed commit matches current authoritative SpaceDO HEAD
- BuildCustom sees the matching revision
- appropriate preview/browser/runtime verification succeeds
- no uncommitted follow-on edits
- no unresolved build errors
- no pending clarification
- no resource-boundary state

A genuine verified no-op may have a separate completion path.
