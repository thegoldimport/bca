## Artifact reproduction limit and decision

The prior clean public-main build produced `/tmp/vibesdk-baseline/dist/vibesdk_production/index.js` (SHA-256 `9dac822f921f4411a3e91d6bc449c0acc16cbaf865fdf5a076c5bc10af56a8fa`, 12,132,392 bytes). The protected multipart `index.js` part is approximately 12.1 MB (extracted text SHA-256 `f76ee44f874a5a110af28987e266e89b2a380fd430f9f7b6d2bc9ff8094748bc`, 12,099,920 characters under that extraction). **They are not byte-identical.** The protected build used a redirected production-specific Wrangler config and a deleted local checkout; neither its complete historical source nor exact package/toolchain installation is available. No difference was silently normalized as nondeterministic. The previous candidate build is an existing reference build, not a recreated September 18 upload. No new historical candidate was deployed or installed in the main workspace.

**Strongest matching source:** public main `9da158d...` because both restore methods and every logged client-file path match its build. It is **not unique**: 33 public revisions share the two patch targets and root lock, some changes cannot be resolved from the available module fragments, and a modified deleted checkout cannot be excluded. **Strongest matching dependency state:** that group's shared root `bun.lock` plus the observed Wrangler 4.90.0, but the protected lock and historical Bun/Node versions remain unknown. Exact artifact match: **NO**. Unique structural source match: **NO**. Classification remains **PROVENANCE STILL AMBIGUOUS**, not “unrecoverable,” because a missing upload-time archive or operator record could still resolve it.

**Recommended next path: B1, with a strict boundary.** For the bounded, enumerated public candidates, the frozen source patch applies identically, but that is **not** a production safety decision. Before constructing any candidate, obtain the deleted temporary checkout's archived build inputs or another authenticated source-to-version record and prove whether the protected upload belongs to that bounded set; if that cannot be done, separately establish a stronger complete-bundle and existing-state compatibility argument. Do not apply, adapt, build for production, deploy, upload, switch traffic, change runtime operations, or attach `app.buildcustom.ai` as part of this recommendation.
