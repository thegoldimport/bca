---
name: Runtime cutover capability disagreement
description: Guarded production runtime activation yielded a false live registration capability despite correct version and binding checks.
---

In a guarded public-signup activation, deployment readback showed the intended runtime version at 100% and the old version at 0%. The candidate configuration recheck had shown registration enabled, but both a targeted version-override capability request and an ordinary live capability request failed the required `registrationEnabled=true` observation. Existing-user authentication passed. The runtime was restored to the closed version without activating the control candidate or retrying. In a later, separately authorized attempt, the ordinary candidate request returned registration enabled with candidate-version tail evidence, while the targeted override request returned registration disabled and had no matching tail. The operator restored the closed runtime; its immediate targeted closed tail also missed, but an independent closed observer then passed for both targeted and ordinary requests.

**Why:** Cloudflare deployment and binding readbacks alone did not prove the live runtime capability. The preserved operator journal summarized failed checks but not raw responses or per-request versions, so its exact cause remains unknown. For this container/Durable Object Worker, Cloudflare reported no Version URL, and version overrides require the target in the current deployment. Tail correlation has missed individual requests despite nearby matches. A separately authorized, guarded runtime-only diagnostic once correlated both candidate requests to the candidate itself and observed correct registration capability and existing-user auth; it then restored the closed runtime. That did not establish why either cutover attempt failed, and a passing ordinary request cannot replace a failing targeted one.

**How to apply:** Keep candidate configuration, targeted capability, and ordinary live capability as separate required gates. Redact CSRF tokens and cookies from capability responses, but capture safe response details and correlate each request to a tail version. Treat missing per-request tail as UNKNOWN and fail closed, even if a nearby request correlated. Do not infer an earlier failure's cause from a later pass, or reuse a prior activation authorization. A final signup cutover requires its own permission and closed-state precheck.
